# 分支上下文预算：远祖先换成缓存摘要，锚文本与当前分支保持原文

审计 P1-3：上下文 = 根→当前路径全部消息（D-107），第 4 层已 ~61k 字。借鉴 BranchBook 的"摘要继承"：`build_context` 设字符预算（`CONTEXT_BUDGET_CHARS`，默认 24000），从当前节点向上保留原文，超预算的祖先节点整节点替换为一条摘要 system 消息；**当前节点消息与各级锚文本永远原文保留**。摘要按节点缓存在新表 `node_summary`（外挂，不改 message，符合 D-101），以节点消息数为版本，消息增加即失效重算。摘要器默认是确定性抽取（锚文本 + 每条消息开头，≤600 字）：零成本、零延迟、测试稳定；`CONTEXT_SUMMARY=llm` 时改调模型压缩，失败回落抽取。另外当前分支的锚文本以【本分支锚文本】system 消息原文放入上下文（此前锚文本只用于检索，模型看不到）。实现集中在 `server/context.py`。这偏离了 D-107"路径消息全量"的字面，但保留其语义（只有路径上的内容进上下文，兄弟/子节点不进）。

**Considered Options**：只截断最旧消息（简单，但会丢掉根问题与锚文本——深挖最需要的定位信息）；按 token 精确计数（需 tokenizer 依赖，中文 1 字≈1 token 的字符预算已足够保守）。
